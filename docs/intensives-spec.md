# ТЗ: интенсивы, годовой календарь, план анонсов по шаблонам

Источник истины для реализации. Ключевое правило: **интенсив — новый самостоятельный контекст работы, а не перезапись дат пространства и не сброс общей истории шаблонов.** Приоритет — сохранить работающие сценарии; новую механику вводить обратно совместимо.

## 1. Что есть в коде сейчас (ограничения)
- У `WorkspaceConnection` одна пара `startDate/endDate`; подключение принадлежит одному пользователю; для одного Rocket.Chat-сервера существуют подключения разных сотрудников (доступ: владелец + `WorkspaceAdminAssignment`).
- У `ScheduledMessage` есть `sourceUserTemplateId`, `sourceOfficialTemplateId`; статусы PENDING/SENT/FAILED/CANCELLED. Статус шаблона сейчас считается по сообщениям пространства.
- Нельзя: перезаписывать даты пространства; удалять старые сообщения для «сброса»; считать прогресс по видимой странице списка; смешивать организационное пространство и персональные подключения (чужие токены не раскрывать).

## 2. Модель работы
- **Организационное пространство (OrgSpace)** — постоянный объект (общее расписание для персональных подключений одного пространства). Нужна минимальная сущность, **секреты не переносить**. Связь подключений подтверждает LEAD_SUP; совпадение URL — только подсказка, не основание автоматически объединять права и данные.
- **Интенсив** — запуск внутри OrgSpace: название, период (включительно), IANA-часовой пояс, описание. Несколько в одном пространстве (прошлые/текущий/будущие).
- **План анонсов** — пункты (день N, время, канал, снимок шаблона). Пункт ≠ сообщение: он связывается с реальной отправкой только после подтверждения сотрудником.
- **Сообщение** остаётся существующим объектом: `Пространство → Интенсив → Пункт плана → Сообщение`. Сообщения без интенсива работают как раньше (новые связи nullable).

## 3. Права (сервер проверяет всё)
| Действие | Кто |
|---|---|
| Создать/изменить/опубликовать/отменить/архивировать интенсив, менять состав плана, пропускать пункт | LEAD_SUP |
| Смотреть опубликованные интенсивы | пользователи с существующим доступом к пространству (владелец/назначенный подключения, привязанного к OrgSpace) |
| Планировать сообщения из пунктов | кому это уже разрешено (`messages:create`) |
| Отправка «от имени» | только по существующим правилам |
| Редактировать/отменять/повторять сообщения | по действующим правилам |
- Выбор интенсива не выдаёт доступ к пространству. Участие в интенсиве не продлевает срок доступа пользователя.
- Общий прогресс не раскрывает чужие приватные шаблоны и недоступный текст сообщений. Если пользователь видит часть плана — UI пишет «Доступные вам анонсы».
- Черновики видит только LEAD_SUP.

## 4. Управление интенсивами
Поля: пространство (обяз.), название (обяз.), дата начала, дата окончания (окончание включается), часовой пояс (IANA), описание, набор шаблонов (при создании или позже). После создания — **черновик**; публикация делает видимым сотрудникам и в календаре. Создание/публикация **не запускают отправки**.
Проверки: окончание ≥ начала; период может пересекать границу года; пересечение **опубликованных** интенсивов одного OrgSpace запрещено; пересечение черновиков — предупреждение и блок публикации; сервер защищает от одновременной публикации конфликтующих периодов (транзакция + advisory lock). Одинаковые даты в разных пространствах допустимы.
Состояния хранятся: Черновик / Опубликован / Отменён / Архивирован. Для опубликованного вычисляются по датам (в часовом поясе интенсива): Предстоящий / Идёт / Завершён. Завершение периода **не** отменяет сообщения и **не** архивирует пространство.

## 5. Годовой календарь
Переключатель Год / Месяц / Неделя / День. Год: строки — пространства (OrgSpace), горизонтальная шкала месяцев, интенсив — полоса, вертикальная отметка «сегодня». Выбор полосы → панель: название, пространство, период, часовой пояс, текущий день интенсива, прогресс анонсов, кнопки «Открыть план» и «Открыть календарь сообщений». Мобильный — список интенсивов по месяцам. Фильтры: год, пространство, предстоящие/текущие/завершённые, только доступные; черновики — LEAD_SUP; отменённые/архивные — отдельный фильтр. Годовая выборка включает интенсивы, пересекающие год; даты показываются в поясе интенсива; тексты сообщений за год не грузятся; прогресс считает сервер.

## 6. Выбор интенсива в пространстве
Над вкладками блок: «Октябрьский интенсив · 12–25 октября · День 3 из 14 · Москва · Выбрать другой ▾». В списке будущие/текущие/прошлые и «Без привязки к интенсиву». Первоначальный выбор: 1) явный интенсив в URL (`?intensive=`), 2) текущий опубликованный, 3) ближайший будущий, 4) без привязки. Выбор фиксируется в контексте страницы (не переключается в полночь/при обновлении данных); URL сохраняет выбор; при смене пространства проверяется принадлежность.

## 7. Вкладка «Шаблоны»
Верх: «План анонсов · Октябрьский интенсив — Выполнено 8 из 24 · Запланировано 10 · Требуют внимания 2»; рядом выбор интенсива, фильтр по дню, фильтр по состоянию, переход к истории; подробности — в подсказке «Как считается прогресс» (вместо длинного абзаца).
Группа дня: «День 1 · Понедельник, 12 октября / 4 анонса · Выполнено 2 из 4» (для будущего интенсива сразу реальные даты; без повтора «День 1 — День 1 (пн)»).
Строка: рекомендуемое время, канал, название, состояние в выбранном интенсиве, кто запланировал/отправил (если доступно), основное действие, меню.
Кнопка «Отправить» → **«Запланировать»**. Основное действие по состоянию:
| Состояние | Действие |
|---|---|
| Не запланировано | Запланировать |
| Запланировано | Открыть сообщение |
| Отправлено | Посмотреть отправку |
| Ошибка | Открыть ошибку |
| Отменено | Запланировать заново |
| Пропущено | Посмотреть причину |
Повтор после успеха — отдельно «Запланировать повтор». Копирование текста — отдельное действие, прогресс не меняет. Выполненные пункты не должны выглядеть как неотправленные (не одни и те же зелёные кнопки).
Личные шаблоны сотрудника **не входят** в общий обязательный план; для них блок «Мои дополнительные сообщения».

## 8. «Обнуление»
Новый интенсив = новый план (новые записи на основе тех же шаблонов); старые сообщения/статусы не меняются и не переносятся; открытие прошлого интенсива показывает его историю. **Никаких cron-сбросов статусов.** Изоляция — связями данных. В режиме «Без привязки» — старый смысл, но с подписью «История использования вне интенсивов», не смешивать с прогрессом интенсива.

## 9. Состояния и прогресс
Ключ учёта — **id пункта плана конкретного интенсива** (не templateId). Состояния: Не запланировано; Запланировано; Ожидает отправки после назначенного времени (вычисляемое уточнение PENDING с прошедшим временем); Отправлено; Ошибка; Отменено; **Пропущено** (явное решение LEAD_SUP с причиной).
Несколько отправок: показывать детали («Отправлено · 1 отправка», «Повтор запланирован на завтра», «Отправлено · Повтор завершился ошибкой»); успех не скрывает ошибку повтора. Прогресс раздельно: выполнено / запланировано / не запланировано / есть ошибки / пропущено; пункт с несколькими успешными отправками = выполнен один раз; пропущенные не считаются отправленными («Отправлено 18 из 24 · Пропущено 2 · Осталось 4»). Прогресс считает сервер по полной доступной выборке, не по пагинации.

## 10. Формирование плана (снимок)
Сохранять снимок: название, текст, источник и тип (официальный/пользовательский), роль/категория (audience), номер дня, рекомендуемое время, канал, версия источника (updatedAt/hash). Изменение/удаление исходного шаблона не меняет план прошлого интенсива и тексты созданных сообщений. Для текущего плана предложить LEAD_SUP «Доступна новая версия шаблона → отличия → Применить» — **только для пунктов без созданных отправок**.

## 11. Даты
День N = дата начала + N − 1 календарных дней (без пропуска выходных). Если день шаблона вне интенсива → пункт «требует настройки»; если день/время не заданы — выбирает сотрудник; прошедшая рекомендованная дата не переносится автоматически на сегодня; дата вне периода интенсива не разрешается (для подготовительных — режим «без привязки»). Даты интенсивов — календарные (DATE); моменты отправки — UTC через пояс интенсива; неоднозначное/несуществующее локальное время (переход DST) требует явного решения.

## 12. Планирование из пункта
Сотрудник выбирает интенсив → открывает пункт → форма получает снимок текста + рекомендуемые дату/время/канал → проверяет отправителя → сервер проверяет доступ, принадлежность пункта и параметры → создаётся обычное сообщение существующего механизма → связывается с интенсивом и пунктом → после ответа сервера обновляется прогресс. Итог перед сохранением: «Интенсив: … / День 2 · 13 октября, 10:00 · Москва / Канал: #support / Отправитель: Анна». Никакой автоматической смены отправителя на владельца пространства. Ручное редактирование текста сохраняет связь с пунктом (можно показать факт изменения).

## 13. Конкуренция
Два сотрудника на одном пункте: первая успешная операция создаёт отправку; вторая получает конфликт «Это сообщение уже запланировано» (409) и предложение открыть существующее; текст второй формы не теряется. Защита — на сервере, транзакционно (в т.ч. частичный уникальный индекс: одна активная отправка на пункт). Повтор HTTP-запроса после сетевого сбоя не создаёт дубль (idempotency key). Повтор после успеха — отдельное явное действие.

## 14. Изменение дат и отмена
Изменение дат: черновик без сообщений — можно пересчитать рекомендуемые даты. Если сообщения созданы: показать затронутые пункты и отправки; **не менять** время существующих сообщений автоматически, не менять отправленные; пункты без отправок можно пересчитать; сообщения вне новых границ требуют решения до сохранения изменения. Без массового скрытого переноса. То же для смены часового пояса.
Отмена интенсива: если есть ожидающие отправки — показать список, потребовать явного решения; по умолчанию блокировать отмену до разрешения (отменить сообщения явно / оставить без привязки? — решение пользователя); обработку «уже идёт» не обещать останавливать. Архив интенсива отделён от архива пространства; завершение интенсива не запускает удаление архивного пространства/данных.

## 15. История
Для интенсива: пункт, снимок шаблона, автор планирования, отправитель, назначенное и фактическое время, результат, причина ошибки, ссылка на RC, изменения и отмены. Попытки — только с момента появления серверного учёта (старые данные не выдумывать). Удаление сообщения в RC не отменяет исторический факт отправки. Каскадное удаление пользователей/подключений/шаблонов не должно уничтожать историю интенсивов (SetNull/Restrict + события истории хранятся независимо).

## 16. Данные (логически)
OrgSpace; Intensive; IntensivePlanItem; ScheduledMessage.intensiveId/planItemId (nullable); IntensiveEvent (история); (позже) попытки отправки. Старые поля дат и ссылки на шаблоны сохраняются. Старый API принимает обычные сообщения без интенсива.

## 17. Миграция данных
Текущие `startDate/endDate` подключений — **предложить** LEAD_SUP как черновик первого интенсива, не публиковать автоматически, не перезаписывать старые поля. Старые сообщения остаются «Без привязки»; не привязывать по попаданию даты в диапазон. Отдельный инструмент LEAD_SUP: выбрать интенсив → кандидаты → проверить → подтвердить привязку; операция идемпотентна, **не** меняет текст/время/автора/отправителя/статус.

## 18. Интерфейс и загрузки
Общие компоненты: выбор интенсива, полоса интенсива, сводка прогресса, строка пункта плана, панель деталей, итог параметров отправки, блок ошибки с повтором, подтверждение несохранённых изменений. Первая загрузка — skeleton по форме; обновление — данные остаются; ошибка загрузки ≠ «План пуст»; при смене интенсива действия недоступны до загрузки; поздний ответ не перезаписывает новый интенсив; сохранение подтверждается только ответом сервера; ошибка не очищает форму; массовый импорт показывает реальное число обработанных.

## 19. Этапы и флаг
Аудит → визуальные улучшения → интенсивы и годовой календарь → планы шаблонов → привязка новых сообщений → история и перенос → доп. функции. Новый интерфейс включается **флагом** (SystemSetting `feature:intensives`); отключение скрывает новые возможности, но не удаляет данные и не останавливает запланированные сообщения.
Вне этого релиза: серии сообщений, копирование плана, переменные шаблонов, командное меню, история попыток отправки, автоповторы.
